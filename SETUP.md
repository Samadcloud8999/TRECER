# Обновить свой Vercel-проект до Кармана 2.0

## 1. Сохрани старые данные

Открой уже работающий сайт → Настройки → Скачать резервную копию. Сохрани JSON. Не очищай данные браузера и не меняй основной домен проекта.

Распакуй новый ZIP. Замени файлы того же GitHub-репозитория содержимым папки `pocket`. Добавь новые папки `supabase`, `src/social`, `scripts` и новые серверные файлы. Удали прежний неиспользуемый `server/push.js`, если он остался в репозитории. Не загружай `node_modules`, `.env` или `.env.local`. Пока Supabase не настроен, продолжит работать локальный дневник.

## 2. Создай Supabase-проект и базу

1. Открой https://supabase.com/dashboard и создай проект. Сохрани пароль самой БД отдельно.
2. Открой SQL Editor → New Query. Скопируй **весь** файл `supabase/schema.sql` и выполни. Он рассчитан на первый запуск в новом проекте, повторно запускать поверх уже созданных таблиц не нужно.
3. Проверь наличие таблиц profiles, entries, reminders, messages, friendships, diary_settings и bucket `media` (закрытый). SQL включает Realtime для таблиц, RLS и ограничения. Не делай bucket публичным и не отключай RLS.
4. В настройках API скопируй Project URL, клиентский anon/publishable ключ и отдельный service-role/secret ключ. Клиентский ключ можно использовать в браузере; service-role только на сервере.
5. Для управления хранением включи доступные резервные копии БД/Storage и контролируй лимиты тарифа. Платёж/платная подписка автоматически не подключаются этой сборкой.

## 3. Подключи Google-вход

1. В Google Cloud Console создай проект и настрой OAuth consent screen. Выбери аудиторию, заполни название и контакт. Для режима Testing добавь свои Google-аккаунты и друзей в Test users; иначе они не смогут войти. Для доступа всем пользователям переведи OAuth-приложение в Production и выполни требования Google.
2. Создай OAuth Client ID → Web application.
3. Authorized JavaScript origins: `https://ТВОЙ-ДОМЕН-VERCEL` (без завершающего пути).
4. Authorized redirect URIs: `https://PROJECT.supabase.co/auth/v1/callback` — скопируй точный callback из Supabase, не подставляй домен Vercel вместо него.
5. Supabase → Authentication → Sign In / Providers → Google: включи Google, вставь Client ID и Client Secret. Client Secret не нужен в Vercel и не попадает в браузер.
6. Отключи Email/Password и другие провайдеры регистрации. Серверный SQL дополнительно допускает создание только Google-аккаунтов. Не отключай разрешение на создание новых Google-пользователей, если друзья должны регистрироваться.
7. Supabase → Authentication → URL Configuration: Site URL = `https://ТВОЙ-ДОМЕН-VERCEL`; Redirect URLs включают `https://ТВОЙ-ДОМЕН-VERCEL/`. Для локальной разработки можно добавить `http://127.0.0.1:5173/`. Для Preview-доменов настрой соответствующие разрешённые URL. Не разрешай произвольные домены.

## 4. Переменные Vercel

Открой текущий Project → Settings → Environment Variables. Добавь в Production (и в Preview, если хочешь тестировать Preview):

| Имя | Значение |
|---|---|
| VITE_SUPABASE_URL | URL Supabase-проекта |
| VITE_SUPABASE_ANON_KEY | Только anon/publishable ключ |
| SUPABASE_URL | Тот же URL проекта |
| SUPABASE_SERVICE_ROLE_KEY | Только service-role/secret ключ, никогда не VITE_ |
| ADMIN_USERNAME | `ADMIN` |
| ADMIN_PASSWORD | Пароль администратора, который ты указал в чате |
| ADMIN_SESSION_SECRET | Случайный секрет минимум 32 символа |
| VAPID_PUBLIC_KEY | Публичный push-ключ из следующего шага |
| VAPID_PRIVATE_KEY | Приватный push-ключ из следующего шага |
| VAPID_SUBJECT | `mailto:ТВОЙ-EMAIL` |
| CRON_SECRET | Отдельный длинный случайный секрет |

Генерировать случайные секреты можно в терминале:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Сгенерируй два разных значения для ADMIN_SESSION_SECRET и CRON_SECRET. Пароль админки не включён в ZIP специально: его задают на сервере. Вход будет работать с ADMIN и тем паролем, который ты поставишь в ADMIN_PASSWORD. Утечка публичного кода не раскрывает его.

После изменения переменных сделай Redeploy. Build = `npm run build`, Output = `dist`, Install = `npm ci`. VITE_ настройки встраиваются при сборке, поэтому одного изменения переменной без Redeploy недостаточно.

## 5. Настрой Web Push и планировщик

В папке проекта после `npm ci`:

```bash
npx web-push generate-vapid-keys
```

Скопируй public/private ключи в соответствующие переменные Vercel. После их замены пользователям нужно переподключить Push в Настройках.

Удобный вариант — **планировщик внутри Supabase**:

1. Supabase → Integrations → Cron: включи pg_cron. В Extensions включи pg_net, проверь доступность Vault.
2. Открой `supabase/scheduler.sql`. Подставь HTTPS-домен своего Vercel и **то же значение CRON_SECRET**, которое стоит на Vercel. Затем выполни SQL в Supabase SQL Editor как владелец БД. Этот файл с заполненными секретами не загружай в GitHub.
3. Скрипт кладёт URL и секрет в Vault, закрывает схемы очереди HTTP-запросов и Vault от обычных аккаунтов и создаёт одно задание каждую минуту. Если не хватает прав на закрытие доступа, не продолжай со снятыми ограничениями: используй внешний планировщик ниже.
4. Проверь успешные запуски в Cron Dashboard и HTTP-вызовы в Vercel Logs. Успешное создание очереди HTTP ещё не подтверждает доставку Push — проверь телефон.
5. Для остановки только этого задания: `select cron.unschedule('karman-push-every-minute');`. После смены домена/CRON_SECRET обнови соответствующие значения в Vault.

Этот вариант не использует Vercel Cron. Supabase и Vercel должны оставаться доступными и укладываться в лимиты своих тарифов. Одновременно выбирай один планировщик.

Альтернативный вариант: настрой внешний планировщик HTTPS-запросов раз в минуту:

```text
GET https://ТВОЙ-ДОМЕН/api/cron
Authorization: Bearer ЗНАЧЕНИЕ_CRON_SECRET
```

Нужен сервис, позволяющий сохранить секретный заголовок Authorization. Не передавай секрет в URL. Внешний планировщик позволяет использовать обычный Vercel-проект. Лимиты и стоимость провайдера проверяй отдельно.

Если у тебя Vercel Pro с минутным Cron, добавь в vercel.json поле `crons` (сохрани остальные поля):

```json
"crons": [{"path": "/api/cron", "schedule": "* * * * *"}]
```

Vercel Hobby не поддерживает минутное расписание Cron; поэтому оно не включено в базовый конфиг и не мешает обновить проект. Для своевременных напоминаний в Hobby используй внешний планировщик. Запуск раз в сутки не заменяет минутное расписание.

После публикации: Настройки приложения → Включить звук и уведомления → Подключить фоновые push. **Это нужно на каждом устройстве**, где хочешь получать сообщения. Сервис-worker и сервер работают на HTTPS. На iPhone сначала добавь сайт на экран «Домой» и включай Push из установленного приложения.

События отправляются сервером по сохранённому расписанию, даже если пользователь закрыл вкладку. Задержка зависит от периодичности планировщика, сети, браузера и телефона. Своя загруженная мелодия работает только при открытом приложении; в фоне используется системный звук устройства.

## 6. Перенеси прежний дневник

После Google-входа аккаунт будет пустым. В **том же браузере и домене**, где были старые записи, зайди в Аккаунт → Перенести записи в аккаунт. Эта операция копирует покупки, места, фото и аудио, а старую локальную копию оставляет на месте. Перенос предназначен для пустого аккаунта.

Если браузер/домен другой, используй ранее скачанную копию: Настройки → Восстановить из копии. Восстановление заменяет текущий облачный дневник; перед этим скачай актуальную копию. Чаты не заменяются. У перенесённых мест нет общего доступа по умолчанию — открой запись и поставь «Показывать друзьям», если хочешь поделиться.

## 7. Проверь с другом

1. Оба войдите через Google, задайте разные никнеймы и подключите фоновые Push.
2. Один: Друзья → Сгенерировать код → отправь код другому привычным способом. Второй: Друзья → Войти к другу → введи код. Повторное использование кода не сработает; срок — 24 часа.
3. Создай место с фото, GPS и отметкой «Показывать друзьям». Друг откроет его на карте и сможет построить маршрут. Покупки и закрытые места ему недоступны.
4. Открой Чаты, отправь текст, JPEG и MP4. Проверь отметку прочтения. Закрой приложение получателя и отправь новое сообщение — сервер должен отправить Push.
5. Друзья → выбери друга → Напомнить. Укажи время через 3–5 минут. Получатель увидит событие в своём разделе. Проверь уведомление с закрытой вкладкой.
6. Проверь личное событие таким же способом. Свой звук проверь при открытой вкладке после включения звука.
7. Админка: неброская ссылка «Управление» внизу меню или `/admin`. Введи ADMIN и серверный ADMIN_PASSWORD. Открой профиль и его фото, проверь общий счётчик и онлайн-статус. Активность видимой страницы за последние 75 секунд считается онлайн.

## Если что-то не работает

- Нет Vite: `npm ci` в папке с package.json, дождись завершения, затем `npm run dev`.
- Google redirect mismatch: проверь callback **Supabase**, Site URL, Redirect URLs и режим Google Testing.
- После входа дневник не загружается: проверь полный запуск SQL, RLS и VITE_ ключи. Никогда не исправляй проблему отключением RLS.
- «Failed to fetch» при сохранении/чате: сеть, доступность Supabase и лимиты сервиса. Запись не считается сохранённой, пока сервер не подтвердит её.
- Нет сообщения в реальном времени: проверь Realtime publication; резервный опрос работает каждые 10 секунд.
- Событие есть, но фонового Push нет: проверь разрешение, подписку, VAPID, CRON_SECRET, успешные минутные вызовы `/api/cron` в Vercel Logs и отсутствие ограничений телефона.
- Не работает `/api` в `npm run dev`: Vite не запускает Vercel Functions. Проверь на Production или используй `vercel dev`.
- Админка не входит: проверь SUPABASE_SERVICE_ROLE_KEY, ADMIN_PASSWORD, ADMIN_SESSION_SECRET и HTTPS. После множества ошибок действует блокировка по IP на 15 минут. Cookie защищён Secure, поэтому тестировать админку следует на HTTPS.
- Не видно логотипа: обнови страницу и переустанови ярлык после публикации. Manifest использует PNG, а service worker получает новую версию при загрузке.

Код готов, но проверка реальных Google-аккаунтов и доставки на телефоны возможна только после настройки твоих сервисов. Не считай push подключённым до успешного теста с закрытым приложением.

Официальная документация для настройки: https://supabase.com/docs/guides/auth/social-login/auth-google, https://supabase.com/docs/guides/cron/quickstart, https://supabase.com/docs/guides/functions/schedule-functions, https://vercel.com/docs/cron-jobs/usage-and-pricing.
