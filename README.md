# Карман 2.0

Обновление существующего React-приложения для Vercel: Google-аккаунты, PostgreSQL, облачные фотографии и мелодии, друзья, чат, уведомления и админка. Сохранены расходы, дневные итоги, накопления, диаграммы, карта, погода и локальный дневник.

**Сначала прочитай SETUP.md.** Новые сетевые функции требуют твоего Supabase-проекта, Google OAuth и серверных ключей. Эти сервисы не были зарегистрированы или настроены от твоего имени. В архиве есть весь код и SQL, но нет чужих или выдуманных ключей.

## Запуск

Node.js 22 LTS или новее. В папке `pocket`:

```bash
npm ci
npm run dev
```

В Windows можно дважды нажать `START-WINDOWS.cmd`: он установит зависимости, если их ещё нет, и запустит Vite. Без клиентских ключей Supabase продолжит работать старый локальный дневник; разделы друзей и чатов объяснят, что нужно настроить. После добавления ключей Google-вход обязателен.

`npm run build` создаёт `dist`. `npm run preview` показывает готовую сборку. `npm run setup:check` проверяет наличие настроек без вывода секретов. Vite dev обслуживает интерфейс; серверные `/api` работают после публикации на Vercel либо через `vercel dev` с его переменными.

## Что добавлено

- PNG-логотипы 192/512 px, maskable-иконка, Apple Touch Icon, manifest, кнопка установки при поддержке Chrome, понятная страница без сети.
- Google-вход: новый Google-пользователь создаёт аккаунт, повторный вход открывает существующий. В БД действует уникальность email без учёта регистра. Другие провайдеры регистрации отклоняются серверным триггером.
- Облачный дневник и закрытое хранилище Supabase. Атомарные изменения записей в PostgreSQL. Синхронизация между устройствами каждые 15 секунд и при обновлениях напоминаний. Одновременное изменение одной записи на двух устройствах разрешается последним сохранением.
- Никнеймы из 3–24 символов `[a-z][a-z0-9_]`. Уникальный индекс учитывает регистр, подчёркивания и очевидные замены o/0, l/1, e/3, s/5, t/7. Также отклоняются никнеймы, отличающиеся одной вставкой, удалением или заменой символа в нормализованном имени. Проверка выполняется в БД с блокировкой для одновременных запросов. Это защита от этих форм сходства, а не от любого визуального или смыслового сходства слов.
- Одноразовый случайный код приглашения (24 часа). В БД хранится хеш. Подключение создаёт взаимную дружбу; можно отключить друга.
- Лента моментов друга и карта. Открываются только любимые места с отметкой «Показывать друзьям». Покупки и накопления остаются личными. Маршрут открывается в Google Maps; геопозицию старта получает сам Google Maps после разрешения пользователя.
- Чаты друзей: текст, изображения и видео до 50 МБ, обновления через Realtime и резервный опрос каждые 10 секунд, количество непрочитанных и отметка прочтения. На экране — до 200 последних сообщений. Старые сообщения сохраняются в БД. Новые сообщения нельзя отправить после отключения дружбы; старая переписка и её вложения сохраняют доступ участникам.
- Напоминание другу: дата и время Бишкека, заголовок и текст. Событие появляется у друга, который может изменить/отключить/удалить его. Лимит — 20 таких напоминаний за сутки. Генерация и передача кода означает доступ к этой функции.
- Серверные Web Push для личных событий, напоминаний друзей и сообщений. Сообщения отправляются сразу через API после записи; при сбое остаются в очереди для планировщика. События отправляет планировщик вне зависимости от открытой вкладки. В комплекте есть отдельный SQL для минутного задания внутри Supabase, а также инструкция для внешнего планировщика.
- Админка `/admin`, неброская ссылка «Управление» внизу меню. Серверная проверка логина и пароля, HttpOnly-сеанс на час, ограничение попыток входа. Общие счётчики, до 1000 последних профилей, поиск по ним и просмотр до 200 последних записей пользователя с фотографиями. Счётчики учитывают всю базу. Приватные чаты админка не отображает.
- Онлайн-статус: видимая вкладка посылает heartbeat каждые 25 секунд. Активность за последние 75 секунд означает «Сейчас в приложении». Это приблизительный статус, без истории слежения.
- Перенос старого локального дневника в пустой аккаунт без удаления старой копии. Резервная копия включает фото и аудио дневника; чаты и профили в неё не входят.

## Важные ограничения

Для облака, карты, погоды и чата нужен интернет. Фотографии/мелодии сохраняются в закрытом Storage, короткие подписанные ссылки живут до 5 минут; после отзыва доступа уже выданная ссылка может работать до истечения срока. Фотографии в админке имеют срок ссылки 2 минуты.

Своя мелодия может играть в открытом приложении после явного включения звука пользователем. Закрытый браузер не может проиграть произвольный загруженный звук — Web Push использует системный звук и настройки уведомлений устройства. При активном беззвучном режиме, отсутствии сети, запрете уведомлений, принудительной остановке браузера или энергосбережении доставка/звук могут задерживаться. Это не будильник с гарантированным временем.

На iPhone Web Push требует совместимой iOS и установки веб-приложения на экран «Домой». На Android поддержка зависит от браузера. Нельзя включить уведомления за пользователя без его согласия.

Координаты фото — текущая GPS-точка при записи либо ручной ввод. EXIF старых снимков не читается. Фото HEIC и видео MOV могут не воспроизводиться в конкретном браузере; для совместимости используй JPEG/PNG и MP4 H.264. Карта использует OpenStreetMap, погода — Open-Meteo.

Администратор видит профили и фотографии из дневника; это явно указано на входе и в аккаунте. Его пароль хранится только в настройках сервера, не в JS и не в ZIP. При развёртывании для других людей владелец отвечает за политику хранения, модерацию, стоимость и лимиты используемых сервисов.

## Структура и проверки

`supabase/schema.sql` — таблицы, ограничения, RLS, очередь и серверные функции. `src/Auth.jsx` — Google-сессия и установка. `src/store.js` — облако, `src/local-store.js` — старый IndexedDB. `src/social/` — друзья, чат, аккаунт и админка. `server/` и `api/` — защищённые push, планировщик и админка.

```bash
npm test
npm run test:ui
npm run build
```

SQL проверяется на PostgreSQL-движке PGlite с локальными моделями auth/storage и ролями: уникальность email/никнеймов, приватность, дружба, одноразовые коды, сообщение, напоминание, атомарность и очередь. Только тестовая криптография заменена заглушками; production SQL использует pgcrypto. Интеграционные проверки интерфейса идут в DOM-окружении с заменёнными анимациями. Реальный Google OAuth, HTTPS Push, GPS, камера, визуальный вид и доставка на телефон должны быть проверены после настройки Production. См. CHECKS.md.
